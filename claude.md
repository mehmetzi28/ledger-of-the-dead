Ledger of the Dead: single-file HTML/CSS/JS necromancer RPG.
- index.html is the shipped game, generated from src/ and committed; never edit it by hand. Edit files in `src/`, then run `node tools/build.js` (each `@@include` line in the template becomes that file's exact bytes). `node tools/build.js --check` fails if index.html differs from src/ (run-tests.js and CI run it first). serve.js rebuilds automatically when a src file is newer, so edit and refresh.
- src/: `index.template.html` (page shell and markup), `style.css` (all CSS); game logic, in this order: `game-data.js` (ranks, gates, roster, secret bosses, items, drop tables, gear rolls, Hell Tower, the DIFF block), `game-player.js` (player stats, new game, backups, save slots and codes, normalizeSave, titles), `game-runs.js` (dungeon runs, combat, bag, raising), `game-skills-market.js` (skills, gold and the market, minion traits, raids, the Rift, tips), `game-gate-rules.js` (boss abilities, status effects, events, cursed gates, omens, gate difficulty, history, records, doors, gear sets), `game-faith-story.js` (faith, skill upgrades, minion commands, story and boss voices, torn pages), `game-phases-town.js` (boss phases, elite affixes, town buildings, the Reserve, bounties, ultimates, fusion, item locks, salvage and enchanting, siege nights, the Memorial, loadouts), `game-rival-trials.js` (the Rival and weekly Trials); then UI: `scenes.js` (from the `//==UI==` marker: sound, music, painted backdrops, boss arenas, display settings), `fx.js` (the battle effects layer: draws only, no game rules), `tr.js` (the Turkish tables `TR_DICT` and `TR_RX`), `ui-view.js` (Turkish lookup, view settings, save files), `ui-icons.js` (all icons and painted bosses), `ui-panels.js` (item cards, gear, bag, bestiary, status, gates, titles, tower, market, skills, help, saves, lore, records, history, the Memorial, loadouts), `ui-codex.js` (the Codex, faith and buildings panels), `ui-rival-trials.js` (the rival's icon and arena, the Trial card, Rival and Trial records, their Codex pages), `ui-screens.js` (town, battle, army, raise, doors, events, spoils, defeat, shortcuts), `ui-input.js` (render, actions, input, startup). Game logic goes in the game-*.js files; UI and icons in scenes.js and the files after it. The build joins them in template order, so a top-level statement never spans two files.
- Saves use localStorage key `ledger-of-the-dead-v1`. Keep loadGame backward compatible: every load goes through normalizeSave (repairs/migrates) and applyLoaded.
- Browsers block localStorage on data: pages, so test saves with `node tools/serve.js` (http://localhost:5173, launch config "game").
- Difficulty is tuned with the DIFF block (gates) and the TW constants (Hell Tower). Balance was tested with bots only. The bot lives in tests/balance-test.js: paste it into the browser console with the game open, or load it from the local server (see the top of the file), then run LOTD_BALANCE.run({modes:['market']}). Faster: `node tests/run-balance.js` (options as JSON, e.g. '{"seed":9100}'). The 'full' mode (`'{"modes":["market","full"]}'`) also uses buildings, salvage, enchanting, fusion, bounties and orders; it should land a little above 'market' (about 87% overall vs about 85%, gates 77-91%; it swears faith and plays Hard on cleared gates by default; with `"heat":0` (Normal only) about 91%, the limit: on 2026-11-19 siege and raid pay were pulled back to keep it there). `"off":["fuse"]` switches parts off to measure them. `faith`, `ult` and `heat` options measure the oath, the ultimate and gate difficulty; `LOTD_BALANCE.duel` tests secret masters; the full bot also orders Commander raids (before the day's last run; a raid is an order for tonight: the squad fights the rest of the day and marches when the day ends, keeps its army or Reserve places overnight so a siege raise cannot fill them, and steps back in at dawn; only if those places are gone does it fall back to the Reserve or the gate), uses the Reserve (benches bodies once a gate is cleared and swaps in whoever beats its weakest minion), dives the Rift at the end (reports average and best depth) and learns the six small passives; fights siege nights like rooms (reports sieges fought and held; about 80-87% held), `"off":["raid"]`, `["rift"]`, `["reserve"]` or `["siege"]` measures without them; the Rival plays only in 'full' (so 'market' is unchanged): the bot meets each challenge as a boss room (about 68% won), challenge runs stay out of the gate table, and `"off":["rival"]` measures without thefts and challenges; `LOTD_HTML=path` makes the Node runners load a tuned copy of index.html.
- Tests: `node tests/run-tests.js` runs 466 tests (one file per system in tests/groups/, helpers and runner in tests/game-tests.js, plus a 30-day bot playthrough) against the built index.html in Node with a fake browser; add `market` etc. to run matching tests. Run it after every change. It first checks the build, then runs tests/lint.js on src/*.js, which fails if a `//` comment was dropped into the middle of a one-line statement and swallowed the code after it (put mid-line notes in `/* */` or at the end of the line), or if a stray control character got into a src file. In the browser: load tests/game-tests.js, then `await LOTD_TESTS.load(); LOTD_TESTS.run()`. GitHub Actions runs it on every push. A second server for play-testing with separate saves: `node tools/serve.js 5174` (launch config "playtest"); a third, "scratch" on 5175, is for throwaway visual checks that must not touch either save (a tab on the same port as a game in use makes that game stop saving).
- Fuzzing: `node tests/fuzz.js` clicks random buttons for thousands of steps per seed and checks the same rules after every click; run it after big changes. Don't edit or rebuild index.html while it runs, because each seed reloads the file.
- Dark palette. Blue and purple are only for the Rare and Epic item tiers. Look: worn and textured, not cartoonish (the "Grim realism pass" CSS block; icons are painted through the #paint SVG filter, coloured by MAT (natural colour and material per creature, rank only on the frame) and textured by the tx* patterns that P() lays on every shape; bosses and the Necromancer are hand-detailed with RIM/FOLD); no italic fonts.
- Turkish: Settings > Language. English is written into the page and `trDom` lays Turkish over it after each render from the `TR_DICT` table (numbers as #, keys without outer punctuation). New UI text needs a Turkish entry there; text with names in it uses a pattern in `TR_RX` (names stay English, $n keeps a group, {tn} translates it). Boss speech is translated through a pattern too.
- Libraries only as vendored files in lib/ (now PixiJS 8.23.0, for the battle effects layer in src/fx.js, loaded at runtime); no CDNs except Google Fonts. The game and the tests must work with the library absent.
- Line endings are LF everywhere (.gitattributes). Write files with LF.
